# 接入指南

[← README](../README.md) · [常用接口](常用接口.md) · [模板说明](../templates/README.md) · [编码规范](编码规范.md)

把本库接进一个 STM32H7 / STM32F4 CubeMX（CMake）工程需要两件事：

1. **CubeMX 配置**满足第 1 节的硬性要求（`integrate.py` 会逐条检查，不满足直接报错、不写任何文件）
2. **宿主代码**留出 `user/board`、`user/app`、`user/module`，并在 `MX_FREERTOS_Init()` 里调三个入口

自动接入跑一遍就能完成 2 的绝大部分；本文说明每项要求**为什么**要有，方便自己核对和排错。

## 1. 硬性要求

| 项目           | 要求                                                                  | 为什么                                                                                                                     |
| -------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 芯片           | STM32H7 / STM32F4                                                          | 只包含 `stm32h7xx_hal_conf.h`，DMA 可达区按 AXI SRAM（0x24000000）；**F4**：只包含 `stm32f4xx_hal_conf.h`，DMA 可达区按主 SRAM（0x20000000），CCM RAM（0x10000000，64 KB）不可 DMA                                                   |
| 工具链         | CubeMX → Project Manager → Toolchain = **CMake**              | 脚本改的是 CubeMX 的 CMake 工程结构（`cmake/stm32cubemx/` + `CMakePresets.json`）                                      |
| 语言           | **C++20**：库和宿主应用目标都 `cxx_std_20`                     | 板级实例是 `inline` 全局变量、Config 用指定初始化器（必须按字段声明顺序写）；C++20 下 `volatile` 变量不能用 `++` / `+=`（写成 `x = x + 1U`），见 [编码规范](编码规范.md) |
| RTOS           | FreeRTOS，接口 **CMSIS-RTOS V2**                                | 库内部直接用 FreeRTOS 原生 API（任务、事件组、流 / 消息缓冲），不经 `cmsis_os2.h`；要求 V2 是因为库任务优先级按 `configMAX_PRIORITIES` 往下取、业务任务按 V2 的 56 级（`osPriorityNormal` = 24）排在它们下面，V1 只有 7 级                                                        |
| tick           | `configTICK_RATE_HZ = 1000`                                         | `sys_task` 10 ms、`can_rx_task` 1 ms 都按 tick 折算，非 1 kHz 周期就错                                                 |
| 栈溢出检查     | `configCHECK_FOR_STACK_OVERFLOW = 2`                                | 钩子 `vApplicationStackOverflowHook()` 要把现场写进 `fault_record`                                                     |
| 分配失败钩子   | `configUSE_MALLOC_FAILED_HOOK = 1`                                  | 同上，`vApplicationMallocFailedHook()`                                                                                   |
| HAL 时基       | SYS → Timebase Source 选一个空闲 TIM，**不用 SysTick**         | SysTick 归 FreeRTOS；HAL 超时全靠这个时基                                                                                  |
| 时基中断优先级 | 没有要求，CubeMX 默认的 15 即可（1.4 起；Debug 与 -O2 实测） | 原来要求高于 UART / CAN 的两条理由都已消除，宿主自己的代码还有一条注意事项，见 [2.3](#23-hal-时基) |
| CAN            | **H7**：FDCAN 经典 CAN，RX FIFO0，开 FDCAN 中断，`AutoRetransmission = ENABLE`；**F4**：bxCAN，Normal 模式，RX FIFO0 中断，`AutoBusOff = DISABLE`、`AutoRetransmission = ENABLE`                                     | H7 驱动按 FIFO0 取帧、靠中断做 Bus-Off 自动恢复；F4 用 3 个发送邮箱，过滤器组 0 归驱动独占，恢复由 `service_recovery()` 统一管（所以关掉硬件 ABOM）                                                                               |
| UART           | 中断模式开全局中断 或者 DMA 模式再配 RX/TX DMA 与 DMA 中断            | 驱动用 IDLE 中断切帧，再把数据投进 FreeRTOS 流缓冲区；F4 没有硬件 FIFO，`ICBSP_UART_ENABLE_FIFO` 必须为 0                                                                       |
| SPI            | 全双工主机、软件 NSS；H7 还要 `MasterKeepIOState = ENABLE`                  | 片选由 GPIO 手动控制，NSS 引脚不能自动释放总线；F4 的 `SPI_InitTypeDef` 没有 `MasterKeepIOState`，一次片选内多段传输是否出假时钟沿需实测                                                                             |
| 链接脚本       | **H7**：**可加载**的 `.dma_buffer` + `.noinit`；**F4**：只要 `.noinit`                   | `.dma_buffer` 放 `BspUartT` 实例和 DMA 缓冲，H7 必须在 DMA 可达的 AXI SRAM（F4 上该段不生成）；`.noinit` 放 `fault_record`，复位后不清零 |
| D-Cache        | **H7**：保持关闭（不调 `SCB_EnableDCache`）；**F4**：无 D-Cache                                 | 库假定 D-Cache 关闭；要开就得用 MPU 把 DMA 缓冲区配成 non-cacheable                                                        |
| 时钟树         | `board_cfg.hpp` 里 PWM 的 `timer_clk_hz` 与定时器实际输入时钟一致 | 频率 = `clk / (prescaler × period)`，填错蜂鸣器音调、舵机时序就偏                                                       |

库按 HAL 的 `HAL_FDCAN_MODULE_ENABLED`（H7）/ `HAL_CAN_MODULE_ENABLED`（F4）/ `HAL_UART_MODULE_ENABLED` / `HAL_SPI_MODULE_ENABLED` 等宏条件编译，
**没开的外设不会生成对应驱动和任务**——用不到的外设不配是受支持的状态。

### 1.1 库对宿主的依赖：两个文件

库源码只包含宿主的两个文件（`target_include_directories(icbsp PRIVATE user/board)` 让库看得到它们），其余都是宿主自己的事：

| 文件 | 谁包含 | 职责 |
| --- | --- | --- |
| `hardware_config.h` | 只经 `service/system/config_check.hpp` | **完整配置**：功能开关、任务优先级 / 栈深、队列深度、超时。库里没有默认值，缺宏 `#error`、取值与开关依赖 `static_assert`，HAL 模块没开时强制关掉对应开关 |
| `board_instances.hpp` | `bsp/` 的 HAL 回调分发、`tasks/`、`state_tree` | **实例清单**：`ICBSP_CAN_INSTANCES` / `ICBSP_UART_INSTANCES` / `ICBSP_SPI_INSTANCES` 三个 X-macro，展开成按实例处理的代码。它要包含 `board_cfg.hpp`（实例的定义），所以清单里的名字必须是 `board_cfg.hpp` 里看得见的全局实例 |

`board_cfg.hpp` / `board_cfg.cpp`（实例定义与 `board_init()`）和 `app/` 只被宿主自己用，库不包含。

### 1.2 宿主不能再定义的回调

库用强定义接管了下面这些 HAL 回调（`icbsp` 是 OBJECT 库，强定义直接进最终链接）。宿主**不能再定义同名函数**，否则重复定义：

| 外设 | 库占用的回调 | 不在清单里的同类外设 |
| --- | --- | --- |
| UART | `HAL_UARTEx_RxEventCallback`、`HAL_UART_TxCpltCallback`、`HAL_UART_ErrorCallback` | 转到弱函数 `icbsp_unhandled_uart_rx_event()` / `_tx_cplt()` / `_error()` |
| SPI | `HAL_SPI_TxRxCpltCallback`、`HAL_SPI_ErrorCallback` | 转到 `icbsp_unhandled_spi_txrx_cplt()` / `_error()` |
| FDCAN（H7） | `HAL_FDCAN_RxFifo0Callback`、`HAL_FDCAN_TxFifoEmptyCallback`、`HAL_FDCAN_ErrorStatusCallback` | 转到 `icbsp_unhandled_fdcan_rx_fifo0()` / `_tx_fifo_empty()` / `_error_status()` |
| bxCAN（F4） | `HAL_CAN_RxFifo0MsgPendingCallback`、`HAL_CAN_TxMailbox0/1/2CompleteCallback`、`HAL_CAN_ErrorCallback` | 直接忽略（没有转调） |

宿主自己用 HAL 管的外设（不在 `ICBSP_*_INSTANCES` 清单里）要收这些回调时，定义同名的 `icbsp_unhandled_*()` 强函数即可（N30，声明在对应的 `bsp_*.hpp`）。
库没占用的回调照常由宿主定义，例如 `HAL_UART_RxCpltCallback`、`HAL_SPI_TxCpltCallback`、**`HAL_GPIO_EXTI_Callback`**：
用 BMI088 的数据就绪中断时，宿主在 `HAL_GPIO_EXTI_Callback` 里按引脚转调 `imu.on_acc_drdy_isr(&woken)` / `imu.on_gyro_drdy_isr(&woken)`。

另外库定义了弱符号 `__malloc_lock` / `__malloc_unlock`（见 [2.10](#210-newlib)）；FreeRTOS 的栈溢出 / 分配失败钩子、故障异常处理在 CubeMX 生成的文件里，由 `integrate.py` 在 USER CODE 段转调库的 `fault_on_*()`。

## 2. CubeMX 逐项设置

### 2.1 Project Manager

- Project → **Toolchain / IDE = CMake**
- 生成后根目录应有 `CMakeLists.txt` 与 `cmake/stm32cubemx/CMakeLists.txt`
- 建议保留 `CMakePresets.json` 里的 `Debug` / `Release` 预设名：`integrate.py --preset`、`.vscode` 都按这个名字找构建目录

### 2.2 FreeRTOS

Middleware → FreeRTOS：

- Interface = **CMSIS_V2**
- Config parameters → `TICK_RATE_HZ = 1000`
- `CHECK_FOR_STACK_OVERFLOW` = `Option2`
- `USE_MALLOC_FAILED_HOOK` = `Enabled`
- `TOTAL_HEAP_SIZE` 要放得下库任务：`sys_task` 256 字 + `can_rx_task` 512 字 + `can_tx_task` 512 字，
  再加业务任务（具体值见 `hardware_config.h`）

### 2.3 HAL 时基

SYS → Timebase Source 选一个空闲定时器（如 `TIM6`），不要用 SysTick。
CubeMX 会因此生成 `Core/Src/stm32h7xx_hal_timebase_tim.c`；`integrate.py` 找不到会给 `[注意]`。

时基中断优先级用 CubeMX 默认的 15 即可。1.4 之前要求它高于 UART / CAN（数值 < 5），有两条理由，现在都不成立了：

1. **`HAL_DMA_Abort()` 的竞争**：HAL V1.11.6 的 `HAL_DMA_Abort()` 有读-改-写竞争，靠 HAL tick 计超时；旧驱动在串口 IDLE 中断里调它，
   命中竞争时 HAL tick 若不能抢占串口中断就整机卡死（-O2 必现）。1.1 起 RX 改成循环 DMA，中断路径上不再调 `HAL_DMA_Abort()`。
2. **调度器启动前的延时**：第一次 `xTaskCreate()` 之后、调度器启动之前，FreeRTOS 用 BASEPRI 挡住优先级 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`（5）的中断，
   时基是 15 时 HAL tick 不走，`HAL_Delay()` 永远等不完。库在这段时间（`board_init()` 里 BMI088 复位等）改用 DWT 忙等（评审 A3）。

宿主仍要注意第 2 条：**`app_init()` / `board_init()` 里不要调 `HAL_Delay()` 或带超时的阻塞 HAL**，要延时用 `bsp_dwt.delay_ms()`；
中断里也不要调带超时的阻塞 HAL（它们靠 HAL tick 计时）。

### 2.4 FDCAN

- 模式选 **Classic**（不是 FDCAN FD）
- 开 RX FIFO0；TX 的 FIFO / Queue 模式都支持。总线可能被占满、又要保证高优先级 ID 先发时选 **Queue**（按 ID 优先级发；FIFO 按入队顺序发，前面的低优先级帧发不出去会挡住后面的，见 [bsp.md](code/bsp.md)）。DM-MC02 实测工程用 FIFO，Queue 在 C06d 里测过
- **`Auto Retransmission = Enable`**：CubeMX 默认 Disable，`.ioc` 里不写就是关的。关着时帧在仲裁中输给别的节点（或出错）就不再重发、直接丢弃，
  驱动的诊断计数里一条都看不出来。H750 回归宿主实测：两路对发、每 1 ms 突发 0~5 帧时，ID 大的一路丢了 45%，打开后 0 丢失。
  `integrate.py` 的规则 `can_auto_retx` 会查出来并能自动修改
- NVIC 勾上 `FDCANx interrupt 0`（库的收帧、续发、错误状态通知都在中断线 0）
- **`MessageRAMOffset`**：几路 FDCAN 共用一块 Message RAM（2560 字），CubeMX 默认每路都是 0，会互相覆盖。每路占用的字数 =
  标准过滤器数 × 1 + 扩展过滤器数 × 2 + RX FIFO0 元素数 × 4 + TX 元素数 × 4（8 字节数据时每个元素 4 字）；
  例如 1 个标准过滤器、RX FIFO0 16、TX 16 是 129 字，三路就依次填 0 / 129 / 258
- **`StdFiltersNbr`**：建议填 1。库只在它 > 0 时写一条“全部接收”的标准帧过滤器；填 0 时不写（写了会落到 RX FIFO0 的位置，评审 F9），
  靠全局过滤器“不匹配的帧也收进 FIFO0”同样能收到

### 2.5 UART

- NVIC 勾 `USARTx global interrupt`（IDLE 断帧依赖它）
- DMA 模式：RX、TX 各配一条 DMA，并勾对应 `DMAx streamx global interrupt`。RX DMA 配 Normal 也行，`init()` 会改成 Circular + 直接模式；
  循环接收要求串口 / DMA 中断被挡住的时间短于收满半个 `RX_SIZE` 的时间，见 [bsp.md](code/bsp.md)
- **BDMA 外设**（H7 的 LPUART1、SPI6、I2C4、SAI4 等 D3 域外设）只能访问 SRAM4，而 `.dma_buffer` 在 AXI SRAM：这些外设的实例用 DMA 时
  `init()` 返回 `BAD_ARG`（评审 A4）。要用就改中断模式（`uart_mode::it`），SPI 用轮询（`use_dma = false`）
- 波特率要和 `user/board/board_cfg.cpp` 里 `BspUartT` 的 `baudrate` 一致
  （`integrate.py` 会对比 CubeMX 生成的值，不一致给 `[注意]`）

### 2.6 SPI

- Mode = Full-Duplex Master，NSS = **Software**，`Master Keep IO State = Enable`
- 需要中断 / DMA 时对应勾选（BMI088 驱动用中断 + DMA）
- 片选单独拉一个 GPIO 输出，在 `board_cfg` 里传进去

### 2.7 时钟与定时器

`board_cfg.hpp` 里 PWM 的 `timer_clk_hz` 必须等于 CubeMX 时钟树里该定时器的输入时钟。
脚本只能对比 prescaler / period，时钟源算不出来，会提示自己核对。PWM 的 ARR 预装载由 `BspPwm::init()` 打开，CubeMX 里不用管。

**编码器**（`BspEncoder`）：定时器配成 Encoder Mode，**Period 必须是计数器最大值**——16 位定时器 `0xFFFF`、32 位定时器（TIM2 / 5 / 23 / 24）`0xFFFFFFFF`。
增量按计数器位宽回绕计算，Period 不是最大值时 `init()` 返回 `BAD_ARG`（N37）。

### 2.8 链接脚本

CubeMX 生成的 `*.ld` 没有 `.dma_buffer` / `.noinit`，由 `integrate.py` 按
[`templates/linker_sections.ld`](../templates/linker_sections.ld) 插到 `.data` 之前。
放哪个内存区按「起始地址 0x24000000 的 AXI SRAM」自动找（各型号 CubeMX 里可能叫 `RAM_D1` 或 `RAM`），
也可以用 `--ram-region` 指定。细节见 [4.3](#43-链接脚本)。

### 2.9 BMI088（用到时）

两个片选各一个 GPIO 输出；两个数据就绪引脚配成 EXTI（上升沿），NVIC 打开，宿主在 `HAL_GPIO_EXTI_Callback` 里转调（见 [1.2](#12-宿主不能再定义的回调)）。
**不要启动板载加热电阻的定时器**（例如 DM-MC02 的 PB1 / TIM3_CH4）：库不管加热，没有温控时容易损坏硬件。

### 2.10 newlib

`BspUartT::printf()` 打印浮点（`%f`）会走 newlib 的 `malloc`；两个任务同时对不同串口打浮点时会并发进 `malloc`。
库提供弱符号 `__malloc_lock` / `__malloc_unlock`（挂起调度器，评审 A9）；宿主已有自己的锁（例如 CubeMX FreeRTOS 的 newlib 锁策略生成的
`newlib_lock_glue.c`）时以宿主的为准。另外：

- `configUSE_NEWLIB_REENTRANT = 1`（CubeMX 默认）
- 浮点打印要链接 `-u _printf_float`（nano.specs，见 [4.1](#41-cmake-根目录cmakelist文末添加)）
- 库用到两个堆：FreeRTOS 堆（`configTOTAL_HEAP_SIZE`，`xPortGetFreeHeapSize()` 统计的就是它）和 newlib 堆（链接脚本 `.bss` 之后到栈之间），后者 `xPortGetFreeHeapSize()` 统计不到

## 3. 自动接入

在宿主工程根目录：

```bash
python3 Middlewares/Third_Party/ICBSP/tools/integrate.py --dry-run   # 只看将改什么
python3 Middlewares/Third_Party/ICBSP/tools/integrate.py             # 执行
```

脚本做的事（每一步都先判断是否已完成，可重复运行）：

1. 逐条检查第 1 节的前提
2. 链接脚本插 `.dma_buffer` / `.noinit`
3. `FreeRTOSConfig.h` 的 USER CODE 1：`configASSERT` → `fault_on_assert()`
4. `stm32h7xx_it.c` 的 USER CODE 0 与 HardFault / MemManage / BusFault / UsageFault 的 `_IRQn 0` 段：转调 `fault_on_exception()`，故障现场记进 `fault_record`（评审 A5）
5. `freertos.c` 的 USER CODE Includes / 4 / 5 / Init / StartDefaultTask：钩子记现场、`app_init()`、默认任务体转调 `app_default_task()`（模板不再在 C++ 里强定义 `StartDefaultTask`——那只在 CubeMX 把 defaultTask 设成 As weak 时成立；设成 As external 时脚本提示自己定义）
6. 复制 `templates/user/board`、`templates/user/app`（已存在不覆盖），并核对 `board_cfg` 里的句柄 / 波特率 / PWM 参数
7. 复制 `hardware_config.h` 到 `user/board/`
8. 根 `CMakeLists.txt` 末尾接库、C++20、收集 `user/**/*.c|cpp`
9. 生成 / 合并 `.vscode/settings.json`、`tasks.json`、`launch.json`
10. 复制 `Flash/` 烧录脚本
11. 宿主根目录生成 `.clang-format`（沿用库的那一份）与 `.clangd`（编译数据库 + 本机 `--query-driver`）：
    已存在不覆盖；`.clangd` 里有手写配置但没有 `CompileFlags` 时，只把这一段补在最前面
12. 外置 QSPI Flash（启用时）：根 `CMakeLists.txt` 的 `icbsp-options` 生成区、`CMakePresets.json` 的 `*-Internal / *-QspiRam / *-QspiXip`、
    `icbsp_flash_config.h`、`Flash/daplink_qspi.cfg`、`quadspi.c` 的方案 B 提前返回、`launch.json` 的两个调试配置，见 [3.2](#32-外置-flash编译优化与-gitignore)
13. 编译优化（启用时）：同一个生成区里的 `icbsp_optimization(...)`
14. 示例 `.gitignore`：没有就复制 `templates/gitignore`，有就只追加缺的行

常用参数：

| 参数                                             | 作用                                                        |
| ------------------------------------------------ | ----------------------------------------------------------- |
| `--host <dir>`                                 | 宿主根目录（默认：本库作为 submodule 的工程，否则当前目录） |
| `--dry-run`                                    | 只打印将要做的修改，不写文件                                |
| `--preset <name>`                              | 用哪个 CMake 预设的构建目录（默认 `Debug`）               |
| `--board-dir` / `--app-dir` / `--user-dir` | 目录约定（默认 `user/board`、`user/app`、`user`）     |
| `--linker-script`                              | 链接脚本路径（默认从 `cmake/*.cmake` 的 `-T` 参数找）   |
| `--ram-region`                                 | `.dma_buffer` 放哪个内存区（默认按 0x24000000 找）        |
| `--no-hardware-config`                         | 不复制 `hardware_config.h`                                |
| `--no-vscode` / `--no-flash`                 | 不动 `.vscode/*` / 不复制 `Flash/*`                     |
| `--no-clang`                                   | 不生成 `.clang-format` / `.clangd`                       |
| `--external-flash QSPI_RAM\|QSPI_XIP\|INTERNAL\|off` | 启用外置 QSPI Flash 并设默认存放方式（`off` 关闭），见 [3.2](#32-外置-flash编译优化与-gitignore) |
| `--flash-chip <名字>` / `--qspi-prescaler <n>`  | 外置 Flash 芯片（`W25Q64` / `W25Q128` / `W25Q256`）、QUADSPI 预分频（默认 2 → 80 MHz） |
| `--opt 类型=等级` / `--vendor-os` / `--no-opt`  | 编译优化：如 `--opt Debug=-Og`；CubeMX 源码固定 `-Os`；关闭 |
| `--no-gitignore`                               | 这次不复制 / 合并示例 `.gitignore`                        |

行为约定：

- 只改内容仍是 CubeMX 默认的 USER CODE 段；已有自定义内容会报错并说明要手动合并的位置
- 任何一步报错都不写任何文件
- 宿主已有的 `.vscode` 配置、`Flash/` 脚本、`.clang-format` / `.clangd` 不覆盖，只补缺失项（JSONC 注释也保留）
- 工程名取 `CMAKE_PROJECT_NAME`；`device` / OpenOCD target 按 `.ioc` 的 `Mcu.Name` 推出来


### 3.1 按 .ioc 生成实例与设备（`--apply`、Web UI）

除了复制模板，`integrate.py` 还能按 CubeMX 的 `.ioc` 生成板级代码：每个选中的外设一个库实例（FDCAN1 → `bsp_can1`，参数取自 `.ioc`，
H7 的 DMA 实例自动套 `ICBSP_DMA_BUFFER`）、`board_instances.hpp` 的清单、`init()`、`hardware_config.h` 的功能开关，以及可选设备
（DJI / 达妙电机、BMI088、WT102、R9DS、Emm_V5、舵机、蜂鸣器、直流电机）的实例、`init()` 和 EXTI 转调。数据全部来自 `tools/manifest.json`。

**图形界面**（零依赖，不用 `npm install`）：

```bash
node Middlewares/Third_Party/ICBSP/tools/web_ui/server.mjs        # 然后浏览器打开 http://127.0.0.1:8765/
#   --host <宿主根目录>  --port <端口>  --python <python3 路径>
```

页面逐条显示 `.ioc` 校验（能自动修改的可以勾选后修改 `.ioc`，并可选用 CubeMX 命令行重新生成），列出外设与参数、功能开关、可挂设备，
改选择后自动重新预览 diff，确认后写入。页面只负责展示和收集选择，逻辑都在 `integrate.py`；找不到 Python 3.8+ 时页面会提示。

**命令行**：

| 参数 | 作用 |
| --- | --- |
| `--apply <选择.json>` | 按选择生成（格式见 `tools/icbsp_tool/selection.py` 文件头；只写部分键时按默认补齐） |
| `--json` | 只输出一个 JSON：检查结果、外设候选、可挂设备、完整选择、生成区状态、diff（Web UI 用） |
| `--plan` | 同 `--dry-run`：只给 diff，不写 |
| `--fix-ioc all\|规则id,…` | 把能自动修改的 `.ioc` 失败项写进 `.ioc`（先备份成 `.ioc.bak-时间`） |
| `--regenerate` / `--cubemx <目录>` | 用 STM32CubeMX 命令行无界面重新生成（桌面上别开着 CubeMX，会抢锁） |
| `--overwrite-edited` | 生成区被手改过也覆盖（默认停下） |

**生成区**：生成的代码只写在 `// <ICBSP-GEN 名字>` … `// </ICBSP-GEN 名字 哈希>` 之间，区外的内容不动；结束标记里的哈希用来发现手改，
手改过的区默认拒绝覆盖。完整的选择存进板级目录的 `icbsp_selection.json`（随工程提交），下次扫描 / 打开页面从它开始。
手写的板级文件没有生成区，`--apply` 会停下并提示把模板里的标记加进去。

### 3.2 外置 Flash、编译优化与 `.gitignore`

这三项是工程级选项，存在 `icbsp_selection.json` 的 `external_flash` / `optimization` / `gitignore` 三个键里；命令行参数改了它们也会存回去，
下次运行、Web UI 都沿用。Web UI 里对应“外置 Flash”“编译优化”“工程文件”三节。

- **外置 Flash**：`.ioc` 启用了 QUADSPI，且片内 Flash ≤ 128 KB（H750 / H7B0 / H730）或最近一次构建占片内 Flash ≥ 85%（读 `build/` 下的
  ELF 或 `.map`，链接溢出时也算）时，脚本给出 `[注意]`、Web UI 顶部出现建议横幅，一键选方案 A / B。原理、两种方案的取舍、烧录与调试、
  bootloader 状态码、实测数据见 **[外置Flash.md](外置Flash.md)**。OCTOSPI（H723 / H730 / H7B0）暂不支持，脚本会说明。
- **编译优化**：每个构建类型一个等级（`Debug` / `RelWithDebInfo` / `Release`），生成 `icbsp_optimization(...)`：用 `target_compile_options`
  追加在工具链文件的 `-O0 -g3` 等之后（GCC 以最后一个 `-O` 为准），不改 CubeMX 生成的工具链文件。`VENDOR_OS`（Web UI：“CubeMX 生成的源码
  固定 -Os”）让 HAL / FreeRTOS / USB 在所有构建类型下都是 `-Os`，Debug 时自己的代码仍是 `-O0`，H750 上能省二三十 KB。
- **`.gitignore`**：`templates/gitignore`（`build/`、`.cache/`、`compile_commands.json`、`*.su`、`__pycache__/`、`.vscode/.cortex-debug*`、
  `Flash/*.log`、`*.ioc.bak-*`）。宿主已有 `.gitignore` 时只把缺的行追加在 `# >>> icbsp` … `# <<< icbsp` 之间，原有内容不动。

这两项 CMake 内容写在根 `CMakeLists.txt` 的 `# <ICBSP-GEN icbsp-options>` 生成区（`#` 注释的生成区标记，规则同上），
放在 `add_subdirectory(<icbsp>)` 之前：外置 Flash 要先换掉 `-T` 链接脚本，库的链接脚本检查才会检查新脚本。

## 4. 手动接入

不用脚本、或者想核对脚本改了什么时看这一节。

### 4.1 CMake （根目录CMakeList文末添加）

```cmake
add_subdirectory(Middlewares/Third_Party/ICBSP)
target_include_directories(icbsp PRIVATE user/board)
target_link_libraries(${CMAKE_PROJECT_NAME} icbsp)
target_compile_features(${CMAKE_PROJECT_NAME} PRIVATE cxx_std_20)
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE user/board user/app user/module)
target_link_options(${CMAKE_PROJECT_NAME} PRIVATE -u _printf_float)

file(GLOB_RECURSE USER_SOURCES CONFIGURE_DEPENDS
    ${CMAKE_CURRENT_SOURCE_DIR}/user/*.c
    ${CMAKE_CURRENT_SOURCE_DIR}/user/*.cpp)
target_sources(${CMAKE_PROJECT_NAME} PRIVATE ${USER_SOURCES})
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE user)
```

要点：

- `add_subdirectory` 必须在 `add_subdirectory(cmake/stm32cubemx)` **之后**（要拿到 HAL / FreeRTOS 目标）
- `icbsp` 是 **OBJECT 库**：HAL / FreeRTOS 的弱符号回调必须直接进入最终链接，不能做成静态库
- `target_include_directories(icbsp PRIVATE user/board)`：库自身也要看到 `hardware_config.h`
- `-u _printf_float`：`BspUartT::printf` 在 `nano.specs` 下打印浮点必须加，否则输出空 / 乱码
- 宿主应用目标也要 `cxx_std_20`，库的 `inline` 变量与指定初始化器依赖它

### 4.2 `user/board`

从 `templates/user/board/` 复制：

| 文件                    | 作用                                                                              |
| ----------------------- | --------------------------------------------------------------------------------- |
| `hardware_config.h`   | 唯一配置源：任务开关、优先级、栈深、队列深度、超时。只写 `#define`；缺宏、取值范围、开关依赖由库的 `config_check.hpp` 在编译期检查，报错会写明缺哪个宏 |
| `board_cfg.hpp`       | `inline` 外设实例、句柄、参数                                                   |
| `board_cfg.cpp`       | 只放 `board_init()`                                                             |
| `board_instances.hpp` | `ICBSP_CAN_INSTANCES` / `ICBSP_UART_INSTANCES` / `ICBSP_SPI_INSTANCES` 实例名清单 |

`hardware_config.h` 里的功能开关（取 0 / 1）。CubeMX 没开对应外设时库会强制置 0；关掉的模块不编译、对应任务不创建：

| 开关 | 管什么 | 关掉（0）之后 |
| --- | --- | --- |
| `ICBSP_SYS_TASK_ENABLE` | `sys_task`（10 ms） | 没有 CAN Bus-Off 自动恢复与发送兜底、串口巡检、`Online` 掉线计时（`is_online()` 不再变化）、默认状态树总线层的运行期记错（设备掉线照常记）、`sys_task_stats` 与报告回调；DWT 时间轴的回绕跟踪要宿主每隔不到 7.8 s 调一次 `bsp_dwt.get_cycles()`。必须同时关 `ICBSP_UART_PATROL_ENABLE` |
| `ICBSP_CAN_RX_ENABLE` | `can_rx_task`（1 ms）+ `CanRxNodeT` | 不按 ID 分发；DjiMotor / DmMotor 不能用（包含头文件 `#error`）；`BspCanT::receive()` 直接读原始接收缓冲（只允许一个任务读，C12 实测） |
| `ICBSP_CAN_TX_ENABLE` | `can_tx_task` + `CanTxNodeT` | 没有共帧发送、心跳、指令过期清零；DjiMotor 不能用（`#error`），DmMotor 不受影响；只剩 `send()` / `send_latest()` 直接发 |
| `ICBSP_UART_PATROL_ENABLE` | `sys_task` 里的串口巡检 | 串口发送卡死、接收停摆（DMA 出错、HAL 状态卡住）后不再自动恢复 |
| `ICBSP_UART_ENABLE_FIFO` | `init()` 打开 UART 硬件 FIFO | 默认就是 0：保持 CubeMX 的设置，没有损失；开了以后发送卡死恢复时会丢掉 TX FIFO 里最多 16 字节。F4 必须为 0 |

各组合（含逐个关 HAL 模块）都由宿主的编译矩阵脚本验证过 0 error、0 warning（阶段 3）。

`board_cfg.hpp` 示例：

```cpp
inline BspCanT<16, 16> bsp_can1(
    {.hfdcan = &hfdcan1,
     .name = "CAN1"});

inline ICBSP_DMA_BUFFER(bsp_uart1) BspUartT<uart_mode::dma, 128, 128>
    bsp_uart1(
    {.huart = &huart1,
     .mode = UartDir::TxRx,
     .baudrate = 115200U});

inline BspPwm bsp_pwm_buzzer(
    {.htim = &htim12,
     .channel = TIM_CHANNEL_2,
     .timer_clk_hz = 275000000UL,
     .prescaler = 23U,
     .period = 1999U});
```

> 段名一律写 `.dma_buffer.<变量名>`，不要只写 `.dma_buffer`：实例是 `inline` 变量，
> 多个 TU 各 emit 一份弱定义，段名相同时这些数据会全部进同一个输出段（符号去重了、
> 数据没去），表现为段比实例总和大出一整份，或被 `--gc-sections` 剔掉真数据。
> 校验：`nm -S` 里各实例地址首尾相接，段大小 = 实例大小之和（向上对齐）。

`board_instances.hpp` 必须同步：

```cpp
#define ICBSP_CAN_INSTANCES(X) X(bsp_can1)
#define ICBSP_UART_INSTANCES(X) X(bsp_uart1)
#define ICBSP_SPI_INSTANCES(X) /* 无 SPI 实例 */
```

HAL 回调、`sys_task` 巡检、`can_rx` / `can_tx`、默认状态树都按这份清单展开；新增实例只改这里和 `board_cfg.*`。
漏写实例、或清单里两个实例绑同一句柄时，该实例的 `init()` 返回 `BAD_ARG`，`board_init()` 的 `ICBSP_CHECK` 会停在那一行。

`board_cfg.cpp` 里每个外设都要断言：

```cpp
void board_init(void)
{
  // bsp_dwt 已由 system_init() 内部 init()，这里不要再写
  ICBSP_CHECK(bsp_can1.init() == Status::OK);
  ICBSP_CHECK(bsp_uart1.init() == Status::OK);
  // 电机等 CAN 设备也在这里 init()
}
```

失败就地停机，`fault_record` 的行号指出是哪一路。

### 4.3 链接脚本

`.dma_buffer` 必须**可加载**：

```ld
.dma_buffer :
{
  . = ALIGN(32);
  __dma_buffer_start = .;
  *(.dma_buffer)
  *(.dma_buffer*)
  . = ALIGN(32);
  __dma_buffer_end = .;
} >RAM_D1 AT> FLASH
__dma_buffer_load = LOADADDR(.dma_buffer);

.noinit (NOLOAD) :
{
  . = ALIGN(4);
  *(.noinit)
  *(.noinit*)
  . = ALIGN(4);
} >RAM_D1
```

框架在全局构造之前（`constructor(101)`）把 `.dma_buffer` 的初值从 Flash 拷进 RAM_D1。
写成 `NOLOAD` 会让 `BspUartT` 的句柄 / 波特率、`BspSpi` 的句柄 / DMA 配置上电后变成随机值。

CMake 配置阶段会检查：缺段、`NOLOAD`、缺 `AT>` 都直接报错。

### 4.4 入口

`freertos.c` 的 `MX_FREERTOS_Init()` 里调用：

```cpp
system_init();   // 系统状态 + sys / can_rx 任务
board_init();    // 外设实例 init、设备 init、注册 CAN 节点
system_start();  // 有发送节点才建 can_tx，然后置运行位
```

业务任务入口先等运行态：

```cpp
sys_state.wait_running();
```

初始化失败时 `wait_running()` 会删除当前任务，不会跑在半初始化系统上。

## 6. 常见问题

| 现象                                                 | 原因 / 处理                                                                            |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 报「没有 `cmake/stm32cubemx/CMakeLists.txt`」      | CubeMX 的 Toolchain 不是 CMake                                                         |
| 报 `.dma_buffer` 缺段 / 是 `NOLOAD` / 缺 `AT>` | 链接脚本没按 [4.3](#43-链接脚本) 改                                                     |
| 串口参数上电变随机值                                 | 同上，`.dma_buffer` 必须是可加载段（`>RAM_D1 AT> FLASH`）                          |
| `can_rx_task` 收不到帧                             | FDCAN 中断没开，或过滤器没放行                                                         |
| CAN 负载一高就丢帧（多是 ID 大的那一路），驱动的 `diagnostics` 全为 0 | FDCAN 的自动重发没开（CubeMX 默认 Disable），仲裁输掉的帧直接丢弃；见 [2.4](#24-fdcan)。`integrate.py --fix-ioc can_auto_retx --regenerate` |
| 卡在 `wait_running()`                              | 某个 `init()` 返回非 `Status::OK`，看 `fault_record` 的行号                      |
| 浮点打印空 / 乱码                                    | 少了 `target_link_options(... -u _printf_float)`                                     |
| 串口 `init()` 返回 `BAD_ARG`                         | 实例没写进 `ICBSP_UART_INSTANCES`、两个实例绑了同一句柄、DMA 模式没配 DMA，或实例不在 `.dma_buffer` |
| `integrate.py` 报「不是宿主工程根目录」            | 用 `--host` 指到有根 `CMakeLists.txt` 的目录                                       |
| clangd 没有补全 / 跳转                               | 先 `cmake --preset Debug` 生成 `compile_commands.json`，再 Restart language server |
| Debug 一启动就报找不到 `runToEntryPoint`           | 填的符号不存在（旧工程里可能是 `all_init`），改成 `main`                           |
| 烧录 / 复位后调试口卡死，要重新上电                  | OpenOCD 配置里注册了外置 Flash bank（如 OCTOSPI2）；删掉，见 `templates/Flash/README.md` 的实测经验 |
| 烧录脚本连不上 / 下载失败                            | OpenOCD 用 0.12 及以上（`OPENOCD=<路径>` 指定）；部分 CMSIS-DAP 探针要在 `daplink.cfg` 里打开 `cmsis-dap backend hid` |
| 刚烧完 `fault_record` 里有一条 HardFault（BFAR = 0x04C11DB7、tick 0） | OpenOCD 校验时在目标上跑 CRC 程序，被旧固件记下的，可以忽略                              |
| H750 等小 Flash 型号链接报 `region FLASH overflowed`   | 打开外置 Flash（[3.2](#32-外置-flash编译优化与-gitignore)、[外置Flash.md](外置Flash.md)），或先用编译优化 `--opt Debug=-Og` / `--vendor-os` 顶着 |
| 外置 Flash：板子不跑，`0x3800FFE8` 的启动状态不是 0x10 / 0x11 | 按 [外置Flash.md](外置Flash.md) 的状态码表查：5 = QSPI 里没有镜像（先跑 `OpenOCD_flash`）、7 = CRC 不对、3 = JEDEC ID 不符 |
| `.dma_buffer` 里的实例初值错位（句柄为空、`init()` 返回 `BAD_ARG`），`.dma_buffer` 不在 RAM 区开头 | 链接脚本里 `__dma_buffer_load` 要写成 `LOADADDR(.dma_buffer) + (__dma_buffer_start - ADDR(.dma_buffer))`（段内 `ALIGN(32)` 会让起点后移；2026-11-10 起模板已改） |
| 卡在 `bmi088.init()`（SPI 传输不返回；SPIx_SR 里 TXTF 置位、一直没有 RXP） | H7 的 CubeMX 在 `.ioc` 不写 DataSize 时默认 **4 位帧**；改成 8 Bits。BMI088 的 SCK 还不能超过 10 MHz。`integrate.py` 的规则 `spi_8bit` / `spi_bmi088_speed` 会查出来并能自动修改（`--fix-ioc spi_8bit,spi_bmi088_speed --regenerate`） |
| 加了 BMI088 后 `fault_record` kind = 3（分配失败），堆最低余量只剩几百字节 | BMI088 的工作任务（`ICBSP_BMI088_TASK_STACK`）和 VQF 都从 FreeRTOS 堆分配：`configTOTAL_HEAP_SIZE` 调大（回归宿主用 64 KB） |
| Debug（-O0）下 `defaultTask` 栈溢出（`fault_record` kind = 2，tick 很小） | CubeMX 把 `MX_USB_DEVICE_Init()` 放在 `defaultTask` 里，-O0 下 128 字栈不够：FreeRTOS → Tasks → defaultTask 栈改成 512 字 |
