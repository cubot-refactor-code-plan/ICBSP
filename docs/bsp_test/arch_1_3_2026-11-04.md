# 架构问题（undo 1.3）改动与实机回归（2026-11-04）

按 `third_party/stm32_bsp/undo.md` 阶段 1.3 修 fork 引入的架构问题（对比评估 N13 / N14 / N15 / N24 / N25 / N30 / N32 / N36，以及 `.dma_buffer` 宏），
把 SPI / BMI088 测试组适配到新库，新增服务层测试组（Y01 ~ Y05），在 -O2 上做全组回归。

## 环境

- 板、接线、工具链同 `README.md`；宿主分支 `icbsp-migration`，submodule = stm32-framework `626260c` + 1.2 / 1.3 工作区改动。
- FreeRTOS 堆 64 KB；HAL 时基 TIM8 优先级 4。全程没有启动 TIM3、没有写 PB1（BMI088 加热电阻），H00 / H99 与监视任务核对全部为 0。

## 库改动

| 项 | 内容 |
| --- | --- |
| N13（SPI） | `BspSpi::init()` 核对实例在 `BSP_SPI_INSTANCES` 里、且清单里只有它绑这个句柄（`bsp_spi_is_listed()`），否则 `BAD_ARG`。UART / CAN 已在 1.1 / 1.2 做完 |
| N32 | `BspSpi` 改成 constexpr 构造 + 平凡析构 + `deinit()`；`init()` 可重复调用（先 `deinit()`：中止进行中的传输、释放锁与信号量、清诊断计数，再重建），和 CAN / UART 一致。弹跳缓冲加了 `= {}`——不加时构造不是常量表达式，inline 实例会退回动态初始化（测试里的 `constinit` 探针发现的） |
| N14 | `sys_task` 不再用宿主的 `print_uart`：耗时统计写进全局 `sys_task_stats`（`cycles` / `last_us` / `avg_us`（最近 1 s）/ `max_us`），另有 `system_set_report_hook(hook, period_ms)`（默认没有回调，库不打印）。模板与本工程的 `app_main.cpp` 用它每 5 s 打到调试串口 |
| N15 | 删 `CAN_RX_QUEUE_FRAMES` / `CAN_TX_QUEUE_FRAMES`（深度由 `BspCanT<RX, TX>` 模板参数决定）；`CAN_RX_RETURN_FRAMES` 在 1.2 已接回代码，保留；`CAN_BUSOFF_RETRY_MS` 的检查改成 ≥ 10（sys_task 节拍，库里另有 `static_assert`）；`UART_ENABLE_FIFO` 在 1.1 已恢复 |
| N24 | `bsp_pwm` / `bsp_encoder` / `device_servo` / `device_motor` 加 `HAL_TIM_MODULE_ENABLED` 保护，`device_r9ds` / `device_emmv5_group` 加 `HAL_UART_MODULE_ENABLED` 保护 |
| N25 | 模板不再强定义 `StartDefaultTask`，改为 `app_default_task()`；`integrate.py` 把转调写进 `freertos.c` 的 USER CODE StartDefaultTask 段（段内还是 CubeMX 默认内容时才改），defaultTask 设成 As external 时提示自己定义 |
| N30 | 库占用的 8 个 HAL 回调（UART 3、SPI 2、FDCAN 3）在清单比对的 `else` 分支转调弱函数 `icbsp_unhandled_*()`，宿主定义同名强函数就能收到清单外外设的回调 |
| N36 | `EventState`：补 `clear_error()` / `clear_errors()`（只清本实例、不传播、不动失败位）、`error_bits()`；`init_error()` 只在初始化期有效，实例已在运行时降级成 `error()` 并返回 `NOT_SUPPORTED`（N16 / Q6 的教训：运行期错误不能让系统停摆）；`error_code()` 的含义（未清错误里枚举值最小的）写进文档。`Online::update()` 遍历时挂起调度器、每个节点单独进出临界区，`now` 在临界区里取 |
| `.dma_buffer` 宏 | `bsp_dma_buffer.hpp`：`ICBSP_DMA_BUFFER(name)` 展开成 `section(".dma_buffer.<name>")`；库文档、模板、本工程全部改用它 |

## 测试代码改动（宿主 `app/test/`）

- SPI / BMI088 组适配新库：S01 重写（见下）；C++20 下 volatile 的 `++` 改写；其余用例接口没变。
- S01 需要“在清单里、但配置有问题”的实例：`board_cfg.hpp` 在测试开关打开时加 6 个测试实例（hspi1 轮询实例、假句柄实例），经 `BSP_TEST_SPI_INSTANCES` 并进清单。不对 `bsp_spi2` 重新 `init()`——BMI088 的自动刷新任务一直在用它。
- 新增服务层组 `test_service.cpp`（`BSP_TEST_SUITE_SERVICE`，约 5 s，最先跑）。
- 结果表 `BSP_TEST_MAX` 64 → 96，放进 `.dma_buffer`（AXI SRAM；DTCM 在五组全开时已用到 95%）。

| 用例 | 内容 |
| --- | --- |
| S01 | 清单内轮询实例 init / 重入 init / deinit 后 `lock`、`transfer_locked` 返回 NOT_INIT / 再 init；清单内“use_dma 没链 DMA”、“use_dma 在 DTCM”；清单外合法实例、清单外与 `bsp_spi2` 同句柄；清单里两个实例绑同一句柄；空句柄。另有编译期检查：`BspSpi` 平凡析构、`constinit` 常量初始化 |
| Y01 | `sys_task_stats` 1 s 内的周期数、耗时；报告回调 100 ms / 5 ms（取整 10 ms）周期的调用次数、快照递增、取消后不再调用 |
| Y02 | 运行期：`init_error()` 降级（NOT_SUPPORTED，子 / 父仍在运行）、错误码优先级、`clear_error()` 不传播、`clear_errors()` |
| Y03 | 初始化期：`init_error()` 传播到父节点、两者 `complete_init()` 都拒绝；清错后失败位仍粘滞 |
| Y04 | `Online` 超时判定；64 个额外节点每 1 ms 刷新、2 s 内误判离线次数 |

## 结果

### -O2（RelWithDebInfo）+ 5 分钟浸泡，五组全开

83 项：**80 通过、C06c 记录（SKIP）、2 失败（Y01 / Y02，测试自己的错误，修正后复测通过）**。原始表 `raw/2026-11-04_arch13_all_O2_soak5.txt`。

- Y01 第一次失败：1 s 的测量窗口落在 `sys_task` 启动后的 1 s 等待里（只有 21 个周期，平均值窗口还没满）。改成等周期数 ≥ 200 再测。
- Y02 第一次失败：期望值写错。子节点的 BUSY 也传播到了父节点，父节点清错前的 `error_code()` 是 BUSY，不是 TIMEOUT；库的行为符合设计。
- 修正后单跑服务层组（-O2）：**6 / 6 通过**（`raw/2026-11-04_arch13_service_O2_rerun.txt`）。Y01：100 个周期 / s，last 9 µs、avg 9 µs、max 12 µs；100 ms 回调 10 次 / s，10 ms 回调 100 次 / s，取消后 0 次。Y04：64 个额外节点下 0 次误判，`sys_task` 最大维护耗时 50 µs。
